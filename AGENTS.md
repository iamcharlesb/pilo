# Repository instructions

- When writing emails for the user, keep them polite, short, and focused on the request. Include only necessary background; avoid recounting the conversation or extensive history.
- Preserve unrelated work in the parent repository and browser-agent submodule.
- Model versions, provider credentials, pricing and operational limits belong in environment configuration. Never print or commit secrets.
- Keep policy checks and known event handling in application code. A notification must not implicitly start a model, browser action or paid recurring job.
- Agent context consists of compact operating instructions, a separate voice file, and relevant playbooks. Load details on demand; keep model-proposed lessons pending until reviewed.
- Run `npm test` for framework changes and `npm --prefix node/browser_agent test` for browser-runtime changes. Both include secret scans. Browser tests compile into `.test-dist` to avoid the dev watcher.
- The browser agent is a local, single-operator tool. MongoDB change streams do not supply account isolation or exactly-once execution of outward actions.

## Evidence review work when requested by the user

- Explain why a role was critical using concrete responsibilities, organizational dependence and outcomes; a title alone is insufficient.
- Establish the reputation of the specific organization or establishment and the importance of the relevant project, rather than relying only on the employer's name.
- Connect the user's exact contribution and retained components to external reliance, recognition and correctly scoped metrics. Distinguish customer outcomes from individual causation.
- For each source, record its title, product, metric, date, reference link, limitations, best witness and the basis of that witness's knowledge.
- Preserve exact performance-rating labels and salary-revision dates. Separate base salary, cash bonus, equity grants, vesting income and unvested market value; avoid double counting.
- Check pre-filing chronology, consistency with original records, translations, draft-versus-signed status and source provenance before final review.
- Keep private model reviews separate from attorney-facing evidence. Draft correspondence only unless the user explicitly authorizes sending.
